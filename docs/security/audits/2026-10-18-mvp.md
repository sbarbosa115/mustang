# Security audit — mvp — 2026-10-18

- **Branch:** `feature/mvp` at `ef66a0d`, against `origin/main`; audited and fixed on `feature/mvp-security`
  (fixes `770b1de` … `1d79210`).
- **Scope:** the whole MVP, since the app is new: every route under `/api/v1` (88, `debug:router`), their query
  strings and JSON bodies; the two CSV uploads (`POST /imports`, `POST /vehicles/import`) and the import templates;
  everything rendered back to users (customer and user names, notes, messages, templates, vehicle fields and
  `photo_url`, consent wording, import row errors); the emails (appointment reminders, customer emails through
  Mailpit); the worker (`SendReminder`, `ImportVehiclesCsv`, `RunImport`, the mail queue) and the console commands
  (`mustang:seed-demo`, `mustang:messaging:simulate-inbound`); the cross-context SQL read sides (worklist,
  interventions, KPIs, timeline, audit, consent states, customer and team directories, sales team); the session, the
  MFA gate, the same-origin check; config (`security.yaml`, `framework.yaml`, `messenger.yaml`, `.env*`, nginx, PHP).
- **Tools:**
  - `composer audit`: clean
  - `npm audit --omit=dev`: clean
  - secrets in the diff: 12 lines, none a production secret. `backend/.env.test` and `backend/.env.dev` hold test and
    dev `APP_SECRET`s; `backend/.env` holds the dev `MUSTANG_ENCRYPTION_KEY` and an empty `APP_SECRET`. The seed
    password `Mustang-dev-1` and TOTP secret `MUSTANGDEVTOTPSECRET234567ABCDEF` (`AccessSeeder`, `MfaSeeder`, e2e
    support) only exist in seeded dev/test data (`mustang:seed-demo` refuses `prod`); the rest are test fixtures.
    Production must set its own `APP_SECRET` and `MUSTANG_ENCRYPTION_KEY` outside the repository (README,
    "Production"); the app now refuses the dev key in prod (finding 7). Nothing was ever a real secret, so nothing to
    rotate.
- **How it was tried:** against the `mustang-security` stack with curl as each seed role and as `other@` (admin of
  Other Motors): dealership A's ids for every id route, list filters and search by A's phone numbers, foreign ids in
  bodies (assignees, vehicles, deals, customers, templates, routing), the wrong role on every manager/admin route, a
  password-only session against the MFA gate (with path tricks), session fixation on sign-in and MFA verify, logout,
  throttling and timing, cross-origin writes, a CSV import naming the other dealership's rep and phone with an HTML
  and a formula payload. Each fixed finding has a test that failed before its fix.

## Checked, nothing found

**A01 Broken access control**
- *Routes and roles:* `debug:router` and `debug:firewall`: one firewall over everything; `access_control` gives
  `PUBLIC_ACCESS` to health and sign-in only and `ROLE_USER` to the rest of `/api`; `UnauthenticatedRoutesTest`
  proves 401 signed out for every route. Tried as sales: 403 on KPIs, interventions, routing (GET and PUT), audit,
  user create/update/deactivate/MFA reset, imports, import templates, template writes, another rep's worklist
  (`worklist_not_yours`). As manager: 200 on the manager routes, 403 on audit and every user write. Import routes
  carry `#[IsGranted('ROLE_MANAGER')]` on top of `access_control`.
- *IDOR:* as `other@`, dealership A's ids answer 404 on every id route: users, customers (and notes, consents,
  timeline, conversation, archive), deals (stage, vehicle, assignee), leads, vehicles, conversations (read),
  templates (get, delete), appointments (get, cancel), message provenance, consent revoke, MFA reset, deactivate,
  role change. Functional tests use `assertNotFoundForOtherDealership` per context.
- *Foreign ids in bodies:* refused with 404/422 and nothing stored: a deal for A's customer, a deal assigned to A's
  rep, A's vehicle on a deal, an appointment with A's rep, A's customer or A's deal, customer assignments to A's rep,
  routing with A's rep, a lead for A's customer or assigned to A's rep, a message with A's template
  (`SendMessageTest::testAnotherDealershipsTemplateIsNotFound`). A CSV import naming `other@mustang.test` as rep left
  the slot empty; a phone of B's customer created a separate A customer and B saw no change.
- *Lists and read sides:* `deals?customer_id=`, `appointments?customer_id=&user_id=`, `audit?entity_id=&user_id=`,
  `conversations?user_id=`, `customers/lookup`, `customers?q=`, `leads?q=`, `conversations?q=`,
  `compliance/suppressions?q=` with A's ids or phones: empty for B. Every query in `*/Infrastructure/Persistence`
  reviewed: worklist and interventions, KPIs, timeline, audit, consent states, customer and team directories, sales
  team, conversations, vehicles and facets filter on the current dealership, and their joins and subqueries are tied
  to a scoped row (`x.dealership_id = y.dealership_id` or the scoped row's key). `suppressions` is global by design and
  the list shows only values among the dealership's own contacts.
- *Ownership from the session:* tenant, author, uploader, capturer and sender come from `TenantContext`, never the
  body; `lead_id` is not accepted on deals.
- *No signed-in user:* the worker's handlers take the dealership from the message or the record (`getForWorker` by a
  queued id, then the record's `dealership_id`); event handlers take ids from the event and call `*InDealership`
  methods, none reads `TenantContext`; the DataImport adapter signs in only an active user of the import's dealership
  and the Messaging adapter only an active admin of the given dealership, each restoring the previous token in
  `finally`, and events raised during that work are dispatched after it, so no token is carried into the next message.
  Live: an import ran on the worker as the uploader and stayed in its dealership.
- *Files:* uploads are never served back; samples and templates are static files.

**A02 Cryptographic failures**
- Passwords: Symfony `auto` hasher; minimum 12 characters on create. MFA secrets: libsodium secretbox with a random
  nonce (`SodiumEncrypter`), only shown at enrollment (409 once confirmed). Recovery codes: `random_int` over a
  30-symbol alphabet (≈49 bits), stored as SHA-256, single use; TOTP compared with `hash_equals`, each step accepted
  once (a reused code is refused). Audit diffs mask `password_hash`, `secret_encrypted`, `recovery_codes_json` (seen
  live: `[masked]`); no Output DTO carries a hash or secret (`LoginApiTest`, `MeApiTest`).
- Secrets in the repository: dev/test values only (see Tools); finding 7 for the key.

**A03 Injection**
- SQL/DQL: every value bound; dynamic parts are column names from fixed arrays and `%d` limits; the vehicles sort is
  an allow-list `match`. The flagged `SeedDemoCommand` `DROP TABLE` uses names from the schema manager in a dev-only
  command; the flagged shell lines are `passthru` in `tests/bootstrap.php` with `escapeshellarg`.
- LIKE: every search goes through `Like::contains`/`startsWith` (escapes `% _ \`); MariaDB runs without
  `NO_BACKSLASH_ESCAPES`, so backslash is the escape.
- XSS (React): every user text is rendered as React text (a stored `<img src=x onerror=…>` customer name comes back
  as JSON-escaped text); the one `dangerouslySetInnerHTML` (`shared/ui/chart.tsx`) writes CSS from a static config
  (commented in `1d79210`); templates are rendered by plain string replacement into text/textarea; hrefs are internal
  paths or `tel:` built from normalised phones; the MFA QR is a server SVG in an `<img>`; `photo_url` only in
  `<img src>` (finding 4).
- Email: both mailers send plain text through Symfony Mime (no header building); the only Twig template is the SPA
  shell, no `|raw`.
- CSV/formula injection: nothing is exported; import templates are static samples; import row errors are JSON. A
  `=HYPERLINK(...)` cell is stored as text and never written back to a spreadsheet.

**A04 Insecure design**
- Rate limits: sign-in 5/min per IP and email (live: the 6th is 429); MFA codes 5 per 5 minutes per user; there are
  no password-reset or invitation endpoints and no paid SMS/email provider.
- State transitions in the domain: closed leads 409, appointments over 409, deal reopen only to engaged, consent
  already revoked 409, last admin 409 (finding 14 for the race).
- Mass assignment: every write reads a `#[MapRequestPayload]` Input DTO listing its fields; entities are never
  deserialised from the request.

**A05 Security misconfiguration**
- Prod error responses (read from config, not by switching the stack): `ApiExceptionSubscriber` answers
  `{error, message, detail}`; 5xx say "Something went wrong."; unhandled exceptions are logged and rendered by
  Symfony's non-debug renderer in prod; payload and type errors carry no class names, SQL or paths. Profiler, WDT and
  the Vite proxy routes are `when@dev` only; the dev firewall covers only those paths. Monolog in prod writes JSON to
  stderr.
- CORS: no CORS bundle, no `Access-Control-*` headers; the API is same-origin only.
- Cookies: `MUSTANGSESSID` HttpOnly, SameSite=Lax, Secure in prod (finding 9).
- Headers: finding 8.

**A06 Vulnerable and outdated components**
- `composer audit` and `npm audit --omit=dev` clean; versions pinned by `composer.lock` and `package-lock.json`.

**A07 Identification and authentication**
- Sessions, not JWTs. Generic error for wrong password, unknown email and deactivated account (finding 1 for timing).
- Session fixation: a planted `MUSTANGSESSID` is replaced on sign-in, and the id changes again on MFA verify and
  confirm (`migrate(true)`); the pre-verify id is dead afterwards. Logout invalidates the session (old id 401) and
  needs a POST (finding 2).
- MFA gate: a password-only session gets 403 `mfa_required` on everything but `/api/v1/auth/*` and health, including
  `/me`; `..`, `%2f`, `//` and case variants either 404 at the router or are not API routes (finding 3). Enrolling
  again with a password alone is refused once a factor is confirmed; only an admin of the same dealership resets it.
- Privilege change: `SecurityUser::isEqualTo` compares role, password hash and active, so a role change or
  deactivation ends the session on the next request (live: a deactivated rep's session answered 401 at once).
- CSRF: `SameOriginSubscriber` refuses state-changing `/api` requests whose `Sec-Fetch-Site`/`Origin` is not the app
  (live: 403 for a foreign origin, `Origin: null`, `same-site`, a look-alike host, and a `text/plain` form-style
  post); SameSite=Lax on top.

**A08 Software and data integrity**
- Uploads: 10 MB in the app (nginx and PHP allow 20 MB), `.csv`/`.txt` only, stored under `var/uploads/…` outside
  the web root with a generated `Id::new().'.csv'` name (the client name is only a label), never served; the readers
  strip a BOM, check UTF-8 and stream rows; reported errors are capped at 200 (finding 11 for the size of the work).
- Path traversal: the stored path is built from the generated id only.
- Deserialisation: no `unserialize()`; Messenger messages carry ids.

**A09 Logging and monitoring**
- The audit log records every create/update/delete and customer read with actor, dealership, request id and IP;
  successful sign-ins update `last_login_at`; mail failures are now logged (finding 6). Failed sign-ins and 403s are
  not written to the audit log; the framework's security log is the MVP's monitoring.

**Frontend specifics**
- No secrets in the bundle (no `import.meta.env` in the app code). The session is an HttpOnly cookie, not
  `localStorage`. Open redirects: the post-sign-in `from` comes from react-router history state, which another site
  cannot set, and `navigate()` stays on the origin. No `target="_blank"` links.

## Not applicable

- **A10 SSRF:** the server fetches no URL (no HTTP client; the readers open only stored upload paths), and
  `photo_url` is never fetched server-side. The 403 SSRF leads are `$this->request(...)` calls in functional tests.
- **JWT lifetime and refresh** (A07): the app uses a session cookie.
- **HSTS in the app** (A05): set by the TLS proxy in production (README, "Production").
